# Milton status — 2026-09-04

Snapshot of what the weight-fitting loop has and hasn't learned, taken one week
after it started running against live shrub data.

## Short version

The data pipeline is healthy for the first time. The screener's apparent edge
**weakened** as more data arrived. A candidate weight vector is beating the
incumbent out of sample, significantly — but its fitted values are still moving
substantially day to day, so nothing should ship yet.

---

## 1. The pipeline is finally feeding it

|                     | 2026-09-03 | 2026-09-04 |
|---------------------|-----------:|-----------:|
| 20d test days       | 18         | **23**     |
| 20d observations    | 343        | **439**    |
| 1d days             | 19         | **42**     |
| replay fidelity     | 1067/1067  | **2560/2560** |
| unscored 20d backlog| 8,315 → 290| **171**    |

Picks logged per day since the dedup fix:

```
2026-09-01   172 picks / 172 distinct symbols
2026-09-02   171 picks / 171 distinct symbols
2026-09-03   176 picks / 176 distinct symbols
2026-09-04   175 picks / 175 distinct symbols
```

Every pick is a distinct symbol — zero duplicates. Before the fix, 93% of the
calibration table was duplicate rows generated by research failure loops, and
the backtester was grinding through them ahead of real data. It has now pushed
past its old 2026-08-05 ceiling into 08-06.

**Replay fidelity is the gate on everything below it.** Milton re-scores every
logged pick from its stored signals and must reproduce the score shrub actually
recorded. It does, exactly, for all 2,560. If it didn't, every number here
would be measuring a different function than the one in production.

## 2. What it learned: the edge is weaker than it first looked

```
20d mean IC    +0.1425  ->  +0.1011
t-statistic      +2.38  ->    +1.92
```

More data made the incumbent look **worse**, and the t-statistic has dropped
below 2 — the rough line between "probably real" and "can't tell it from
luck".

When this was first measured at +0.1377 (t=2.30) it was called *marginally*
significant, on 18 days, with the thinness flagged. That caveat earned its
keep: the edge did not survive contact with five more days at full strength.
This is the ordinary fate of a promising small-sample result, and it is the
main reason the gate refuses to promote on thin evidence.

## 3. The candidate is strong out of sample — and not converged

```
in  sample: incumbent +0.1134   candidate +0.3892
out sample: incumbent +0.0820   candidate +0.2537
paired      +0.1717 per day,  t = +4.09
watchlist   173 -> 152 names clearing MIN_SCORE

GATE: REJECT — only 9 usable test days, need 12
```

The improvement holds on days the search never saw, and its significance has
risen (t 3.55 -> 4.09). It is blocked purely on the day count, now **9 of 12**.

But the proposed moves have shifted, and two flipped direction:

| parameter        | 2026-09-03 | 2026-09-04 |
|------------------|-----------:|-----------:|
| `rsi_oversold`   | 30 -> 45   | 30 -> **60** |
| `rsi_recovering` | 15 -> 35   | 15 -> 35     |
| `macd_cross`     | 35 -> 20   | 35 -> 20     |
| `macd_bullish`   | 15 -> 10   | 15 -> **30** |
| `sma_support`    | 20 -> 0    | 20 -> **5**  |
| `volume_high`    | 20 -> 0    | 20 -> **10** |

`volume_high` and `sma_support` were being zeroed out; now they are merely
reduced. `macd_bullish` was being halved; now it is doubled.

**That instability is itself information.** Fitted values still swinging this
much with each new day mean the fit is not converged, and nothing should ship
regardless of how good the t-statistic looks.

## 4. What to watch

Three more test days clears the gate's day requirement — roughly a week at the
current rate. That would be the first time milton produces a proposal on its
own rather than under `--force`.

The question to answer before then is whether those four parameters settle. **If
they are still swinging when the day count clears, the right response is to
raise `MIN_TEST_DAYS`, not to accept the first candidate that squeaks
through.** A gate you loosen when it finally says no is not a gate.

## How to read the numbers

**Mean IC** — did the ranking predict anything? Each day, the Spearman
correlation between the score the screener assigned and the alpha each name
actually delivered over the next 20 trading days. +1 is perfect ordering, 0 is
coin-flipping, -1 is exactly backwards. Single-name returns are mostly noise,
so +0.10 is a real edge rather than a small one.

**Why per-day, never pooled** — stocks are only ever compared against others
screened the *same day*. Pooling mixes ordering skill with market beta: a day
when everything rose would look like skill. On shrub's own data the pooled and
per-day numbers disagree in *sign* at the 5-day horizon.

**t-statistic** — could it be chance? Above ~2 means probably real. This is the
number the promotion gate cares about most.

**Paired difference** — candidate and incumbent rank the *same names on the same
day*, so the two ICs can be differenced day by day. That cancels the market
move both share, which is most of the variance, and turns "is A better than B"
into a far more sensitive test than comparing two averages.

**Watchlist count** — how many names clear shrub's `MIN_SCORE` of 30. Ranking
can improve while this moves sharply, which silently changes how many stocks
reach the traders. That is a different decision from how they are ordered, so
the gate blocks a change that moves it more than 25%.
